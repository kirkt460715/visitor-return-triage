# 馆店文创售后记录

工单交接覆盖馆店、商城和合作馆，真实工作语境均使用合成词句。结案和客户通知分别记录。 数据全部为合成业务记录。文件使用 UTF-8 JSON，时间均为北京时间，货币如无单独说明均为人民币分。

## 查阅交接数据

使用 Python 3.11 标准库。在仓库根目录运行 `python3 inspect_delivery.py` 查看交接文件和行数，或在后面加文件名（含 `.json`）查看该文件的第一条记录。这个入口仅供查阅交接资料。

## 数据约定

- `tickets.json` order_line 相同或 linked 指向既有工单时构成同一售后主题。received 是可使用描述的开始时刻，due 是最迟对外处理时点。
- `decisions.json` 同一主题可以多次正式结案，后到的结果更正原标签，selection 标示形成标签的途径。
- `watchlist.json` 单独要求质控资质或调整优先级的业务范围。
- `error_costs.json` 真实类别错派某类别的业务损失权重。
- `rotas.json` 班次开始时刻、同时可承接件数和资质；通用允许常规分类复核，质控必需于质控范围和高损失类别。班次应在工单处理截止前。
- `started.json` 已经领的单据，抽查与疑难的记录保留，运营视为复核中。
- `notified.json` 不能被后续改判覆盖的对外动作。
- `validation.json` 滚动复验的训练时点及观察结束时点，最少有效类样本、运营核准的每件平均业务损失上限和普通样本抽查比例。

## 检查资料

运行 `python3 -m unittest discover -s tests -v`。检查会读取当前交接文件，核对该业务所需的关键原始证据是否齐备。
